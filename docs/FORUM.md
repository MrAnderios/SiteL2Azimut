# Форум

Форум сервера: `/forum` (английский — `/en/forum`). Читать можно без входа. Писать — мастер-аккаунтом кабинета, после того как игрок один раз задал имя. Сессия, CSRF и база те же, что у кабинета (`la2`). Пока кабинет выключен (`NUXT_PUBLIC_CABINET_ENABLED=false`), пункт «Форум» в меню скрыт, страницы показывают, что форум работает вместе с кабинетом, и не индексируются. В старую CMS их не перенаправляет: форума там не было.

Тексты — `forum` в `app/locales/ru.ts` и `en.ts`. Ошибки API приходят кодом (`data.code`), фраза для игрока берётся из `forum.errors`.

## Страницы

| Путь | Что на ней |
|------|------------|
| `/forum` | разделы, статистика, поиск по всем заголовкам |
| `/forum/news`, `/forum/general`, `/forum/clans`, `/forum/questions`, `/forum/bugs` | темы раздела, поиск внутри раздела, новая тема |
| `/forum/t/:id` | сообщения темы; `?page=` и `#p-<id>` ведут к сообщению |
| `/forum/u/:name` | карточка участника и его сообщения, без индексации. Сюда ведут имя в списке на главной и имя автора сообщения. В карточке — регистрация мастер-аккаунта, последний заход на форум и число сообщений. Администратор здесь же видит логин мастер-аккаунта, меняет имя и запрещает писать |
| `/forum/me` | своя карточка, аватар и свои сообщения, без индексации. Логин мастер-аккаунта в карточке виден, если это администратор |

Разделы заданы в `shared/forum.ts`, в базе хранится только ключ. Названия — `forum.categories` в locales.

| Ключ | Кто создаёт темы и отвечает |
|------|------------------------------|
| `news` | только администраторы (`staffOnly`) |
| `general`, `clans`, `questions`, `bugs` | любой игрок с именем на форуме |

На странице 20 тем или сообщений (`forumLimits.pageSize`). Закреплённые темы идут первыми, дальше — по дате последнего видимого сообщения.

Поиск ищет подстроку в заголовке (`LIKE`), не в тексте сообщений. Запрос короче 2 символов не уходит на сервер; длиннее 80 обрезается. Возвращается не больше 30 тем. На странице раздела поиск ограничен этим разделом. Страница с результатами поиска не индексируется.

## Кто что может

Администратор — логин из `NUXT_ADMIN_LOGINS`, как в кабинете.

| Действие | Гость | Игрок с именем | Автор | Администратор |
|----------|-------|----------------|-------|---------------|
| Читать | да | да | да | да, включая скрытые |
| Задать имя | — | один раз | — | может сменить чужое |
| Новая тема | нет | да, кроме «Новостей» | — | да, в том числе в «Новостях» |
| Ответ | нет | да, кроме закрытой темы и «Новостей» | — | да и в закрытой, и в «Новостях» |
| Править текст | нет | только свой | только свой | только свой |
| Удалить сообщение | нет | только своё последнее видимое | то же | любое, в том числе уже скрытое |
| Реакция | нет | да, чужому видимому сообщению | нет на своё | да, кроме своего |
| Закрепить, закрыть | нет | нет | нет | да |
| Удалить тему | нет | свою, если видимых сообщений не осталось | то же | любую пустую |
| Запретить писать | нет | нет | нет | да, кроме себя и других администраторов |
| Загрузить или убрать аватар | нет | да | — | да |

Удаление стирает строку и реакции. Вернуть сообщение нельзя. Кнопка «Удалить» у автора есть только у последнего видимого сообщения темы. Администратор удаляет любое. Если после этого в теме не осталось строк, тема удаляется вместе с сообщением. Счётчик ответов пересчитывается.

Сообщения, скрытые раньше (`hidden = 1`), остаются в базе: обычный читатель их не видит, счётчик ответов их не считает. Вернуть такое может только администратор. Новых скрытых сообщений кнопка не создаёт.

Запрет писать (`forum_profiles.banned`) не даёт создавать темы, отвечать, править текст, удалять сообщения и ставить реакции. Читать по-прежнему можно. На администратора запрет не действует, и забанить администратора нельзя.

Тему можно удалить, только когда видимых сообщений не осталось (все скрыты или их не было). Скрытые строки и реакции на них при этом удаляются вместе с темой. Вернуть тему нельзя.


## Имя

От 3 до 16 символов. По краям — буква или цифра, внутри ещё пробел, `_` и `-`. Два пробела подряд не проходят. Имя уникально. Игрок задаёт его один раз (`POST /api/forum/profile`); повторная попытка — `forum_name_locked`. Дальше имя меняет администратор с карточки сообщения.

## Аватар

На `/forum/me` игрок с именем загружает картинку: JPEG, PNG, GIF или WebP, не больше 1 МБ. Тип определяется по содержимому файла, не по имени и не по заголовку запроса. Аватар виден в строке «Вы вошли как» и в карточке на `/forum/me` и `/forum/u/:name`. Убрать его можно на `/forum/me`. Забаненный аватар менять может: запрет касается тем, ответов, правки текста и реакций.

В текст сообщения по-прежнему можно вставить только картинку по адресу `http` или `https`. Файл в сообщение не загружается.

Файлы лежат отдельно от сборки. Локально это `.data/forum-avatars`. На сервере `current` указывает на релиз, а старые релизы удаляются, поэтому аватар хранится в `/var/www/azimut/avatars`. Другой путь задаётся `NUXT_FORUM_AVATAR_DIR`.

## Сообщения

Новые сообщения пишутся редактором и хранятся как `markdown`. Старые записи с `format = plain` показываются как обычный текст с переносами строк и не переписываются, пока автор их не сохранит заново: правка всегда кладёт `markdown`.

В редакторе: жирный, курсив, подчёркивание, зачёркивание, код, заголовки двух уровней, списки, цитата, блок кода, ссылка, картинка по адресу, горизонтальная линия. Кнопка «Исходный Markdown» показывает тот же текст исходником: его можно править напрямую, повторное нажатие возвращает оформление. Файл в сообщение не загружается — только адрес картинки. «Цитировать» вставляет в ответ имя автора и текст блоком Markdown.

Длина текста — до 5000 символов, заголовка — до 120. Пробелы по краям и перевод строки `\r` снимаются до проверки.

Отрисовка своя, в два шага (`app/utils/forum.ts`, `app/utils/forum-html.ts`):

1. `plain` экранируется. `markdown` разбирает markdown-it с выключенным сырым HTML.
2. В разметку пропускается только список тегов редактора. Ссылка — `http`, `https` или `mailto`, без логина и пароля в адресе; у неё `rel="nofollow noopener noreferrer ugc"` и `target="_blank"`. Картинка — только `http` или `https`, с `loading="lazy"` и `referrerpolicy="no-referrer"`. `javascript:`, `data:` и адреса без схемы не проходят.

## Реакции

Под сообщением две реакции: лайк и клоун. Ставит игрок с именем, не автор этого сообщения. Повторное нажатие снимает свою реакцию. Гость видит счётчик. При наведении на уже поставленную реакцию показываются имена тех, кто её поставил. Закрытая тема и раздел «Новости» реакции не запрещают. Скрытому сообщению реакцию поставить нельзя.

## Лимиты

Окно считается от мастер-аккаунта, поиск — от IP. Администратора не касаются лимиты «первые сутки», лимит правок и лимит реакций.

| Действие | Обычный аккаунт | Первые сутки после регистрации мастер-аккаунта |
|----------|-----------------|------------------------------------------------|
| Задать имя | 10 раз в час | то же |
| Новая тема | 5 в час | 1 в час |
| Ответ | 30 в час | 3 за 10 минут |
| Правка текста | 30 в час | то же |
| Аватар: загрузка и удаление вместе | 10 в час | то же |
| Реакция | 60 за 10 минут | то же |
| Поиск | 30 запросов в минуту с одного IP | то же |

«Первые сутки» считаются по `master_accounts.created_at`, не по дате имени на форуме. Если ответ отклонён (слишком частая отправка и другие коды API), текст показывается у кнопки «Ответить».

## База

Таблицы в базе логин-сервера (по умолчанию `la2`). Права `cms_register` на `la2.*` их уже покрывают, отдельный `GRANT` не нужен.

| Таблица | Что хранит |
|---------|------------|
| `forum_profiles` | мастер-аккаунт, имя, запрет писать, аватар, последний заход |
| `forum_topics` | раздел, автор, заголовок, закрепление, закрытие, число ответов, даты |
| `forum_posts` | текст, `plain` или `markdown`, скрыто ли, даты |
| `forum_reactions` | реакция на сообщение: лайк или клоун, кто поставил и когда |

`replies` — число видимых сообщений минус первое. После удаления и ответа счётчик пересчитывается.

Боевой MySQL 5.1.73 без `utf8mb4`. Таблицы — `utf8` / `utf8_unicode_ci`. Символ, который колонка не принимает, возвращается как кривой текст (`invalid_forum_name` или `invalid_post`), а не как сбой сервера.

На уже работающей базе:

```bash
mysql -u cms_register -p la2 < server/database/forum.sql
```

Скрипт можно запускать повторно: таблицы создаются с `IF NOT EXISTS`, колонки `banned`, `avatar` и `last_seen` и значение `markdown` у `format` добавляются, только если их ещё нет. Для новой установки те же таблицы есть в [`server/database/install.sql`](../server/database/install.sql).

`last_seen` — последний заход на форум: обновляется, когда вошедший игрок открывает страницу форума, но не чаще раза в минуту. Пока игрок ни разу не заходил после появления колонки, в карточке стоит прочерк. Дата регистрации в карточке — `master_accounts.created_at`. Логин мастер-аккаунта в эти ответы попадает только для администратора.

## API

Маршруты форума — для самого сайта. Чужой домен их не вызывает: изменяющие запросы режет `server/middleware/csrf.ts`, сессия — cookie `azimut_session`. Публичная статистика описана отдельно в [API.md](API.md).

Чтение:

| Метод и путь | Кто | Ответ |
|--------------|-----|--------|
| `GET /api/forum` | все | разделы и статистика |
| `GET /api/forum/categories/:slug?page=` | все | темы раздела |
| `GET /api/forum/topics/:id?page=` | все; администратор видит скрытые | тема и сообщения |
| `GET /api/forum/search?q=&category=` | все, лимит по IP | до 30 тем по заголовку |
| `GET /api/forum/me` | сессия не обязательна | имя, вход, админ ли, запрет писать, адрес аватара |
| `GET /api/forum/me/posts?page=` | мастер-аккаунт | свои сообщения, регистрация, последний заход; логин мастер-аккаунта — только администратору |
| `GET /api/forum/members/:name?page=` | все; администратор видит скрытые, id, запрет писать и логин мастер-аккаунта | сообщения участника, регистрация, последний заход |

Запись:

| Метод и путь | Кто | Тело |
|--------------|-----|------|
| `POST /api/forum/profile` | мастер-аккаунт без имени | `{ "name" }` |
| `POST /api/forum/topics` | игрок с именем | `{ "category", "title", "body" }` → `{ "id" }` |
| `POST /api/forum/topics/:id/posts` | игрок с именем | `{ "body" }` → `{ "page" }` |
| `PATCH /api/forum/posts/:id` | автор текста; вернуть скрытое — администратор | `{ "body" }` и/или `{ "hidden": false }` |
| `DELETE /api/forum/posts/:id` | автор последнего видимого или администратор | — → `{ "topicDeleted", "slug" }` |
| `POST /api/forum/posts/:id/reactions` | игрок с именем, не автор сообщения | `{ "kind": "like" }` или `{ "kind": "clown" }`. Повтор снимает свою |
| `POST /api/forum/topics/:id/pin` | администратор | `{ "pinned": true }` |
| `POST /api/forum/topics/:id/close` | администратор | `{ "closed": true }` |
| `DELETE /api/forum/topics/:id` | автор пустой темы или администратор | — |
| `PATCH /api/forum/profiles/:masterId` | администратор | `{ "name" }` |
| `POST /api/forum/profiles/:masterId/ban` | администратор | `{ "banned": true }` |
| `POST /api/forum/me/avatar` | игрок с именем | файл `avatar`, не больше 1 МБ → `{ "avatar" }` |
| `DELETE /api/forum/me/avatar` | игрок с именем | — → `{ "avatar": null }` |
| `GET /api/forum/avatars/:name` | все | картинка; без аватара — 404 |

Необработанная ошибка форума (HTTP 500) пишется в журнал сервиса плагином `server/plugins/forum-log.ts`: `journalctl -u azimut`. Клиенту уходит общий `server_error`.

## Файлы

```
shared/forum.ts                 разделы, лимиты, типы ответов API
server/database/forum.sql       таблицы на уже работающей базе
server/api/forum/               маршруты
server/utils/forum/             чтение, запись, имя, аватар, проверка текста
server/plugins/forum-log.ts     журнал ошибок 500
app/pages/forum/                страницы
app/components/forum/           доска, тема, редактор, реакции, поиск
app/composables/useForum.ts     тексты, текущий игрок, текст ошибки
app/utils/forum.ts              отрисовка и проверки кнопок
app/utils/forum-html.ts         адреса и очистка HTML
app/assets/css/forum.css
```

В карту сайта (`server/routes/sitemap.xml.ts`) входят главная форума и пять разделов на обоих языках. Отдельные темы, `/forum/u/:name` и `/forum/me` — нет. Кабинет, вход и админка по-прежнему закрыты в `robots.txt`; форум открыт.

## Локально

Поднимается вместе с кабинетом: `npm run db:up`, `.env` из `.env.example`, `npm run dev`. Демо-вход `admin` / `azimut` — администратор, имя на форуме `Admin`, в разделе «Общение» закреплена тема «Локальный форум». Сброс базы: `npm run db:reset`. Подробности кабинета — [CABINET.md](CABINET.md).
