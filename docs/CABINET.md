# Личный кабинет

Перенос PHP-CMS (`CMS l2`) в Nuxt. Кабинет работает с теми же таблицами MySQL, что и старая CMS,
поэтому миграция данных не нужна, а старые пароли подходят: мастер-аккаунты — bcrypt,
игровые аккаунты — `base64(whirlpool)`, как ждёт логин-сервер.

## Страницы

| Путь                        | Было                     | Что делает                                                    |
|-----------------------------|--------------------------|---------------------------------------------------------------|
| `/login`, `/register`       | login.php, register.php  | вход и регистрация мастер-аккаунта; `?ref=КОД` — приглашение   |
| `/cabinet`                  | index.php, game_account.php, transfer.php | баланс, игровые аккаунты, персонажи, перевод монет |
| `/cabinet/donate`           | donate.php, payment_status.php | счёт на оплату по СБП, QR, статус, история             |
| `/cabinet/referrals`        | referral.php             | реферальная ссылка, приглашённые, награды                     |
| `/admin`                    | admin.php                | подтверждение платежей, начисление/списание, журнал           |
| `/admin/referrals`          | admin_referral.php       | настройки и предметы реферальных наград, ручная проверка      |

Английские версии: `/en/...`. Тексты — `cabinet` в `app/locales/ru.ts` и `en.ts`.

## Устройство

```
shared/cabinet.ts            настройки (ID монеты, курс, лимиты, серверы), типы API — общие для сервера и фронта
server/utils/                db (пулы MySQL), auth (сессия), passwords, payments, referrals, characters, rate-limit
server/api/auth/*            вход, регистрация, выход, текущий пользователь
server/api/cabinet/*         обзор кабинета, создание игрового аккаунта, перевод монет
server/api/payments/*        счета на оплату
server/api/referrals/*       реферальная страница и проверка наград
server/api/admin/*           админ-панель
server/tasks/referrals/      проверка реферальных наград каждые 10 минут (было cron_referrals.php)
server/middleware/csrf.ts    изменяющие запросы к API — только со своего сайта
server/database/install.sql  схема таблиц для новой установки
app/pages/{login,register}.vue, app/pages/cabinet/*, app/pages/admin/*
app/layouts/cabinet.vue, app/components/cabinet/*, app/assets/css/cabinet.css
```

- **Сессия** — зашифрованная httpOnly-cookie `azimut_session` (ключ `NUXT_SESSION_PASSWORD`), 30 дней.
- **Админы** — логины из `NUXT_ADMIN_LOGINS` (через запятую), раньше было зашито `admin`.
- **Ошибки API** возвращаются кодом (`data.code`), текст для игрока берётся из `cabinet.errors` в locales.
- **Настройки** без секретов (ID монеты 4037, курс, мин./макс. сумма, срок счёта, список игровых серверов) —
  в `shared/cabinet.ts`. Доступы к БД — только в переменных окружения.

## Что изменилось по сравнению с PHP-версией

Поведение то же, но исправлены места, где можно было потерять или задвоить монеты:

- Списание при переводе персонажу и при ручном списании — одним запросом `coins = coins - N WHERE coins >= N`.
  Раньше параллельные запросы могли увести баланс в минус.
- Реферальная награда сначала записывается в `referral_claims` (уникальный ключ), потом выдаётся.
  Раньше при двух одновременных проверках предметы могли выдаться дважды.
- При сбое выдачи предмета в игру монеты возвращаются, а в `donate_log` пишется `transfer_refund`.
- HWID и IP для защиты от твинков в реферальной программе собираются по каждой таблице отдельно.
  В PHP-версии ошибка запроса к `la2x.accounts` (на которую нет прав) обрывала сбор, и HWID фактически
  не проверялся. Теперь проверка HWID работает, как задумывалось.
- Ограничение частоты: вход (10 попыток на логин и 20 на IP за 15 минут), регистрация (5 в час с IP),
  создание счетов и игровых аккаунтов.
- Тексты ошибок БД больше не показываются игрокам (в PHP был включён `DEBUG_DB_ERRORS`), только пишутся в лог.
- Реферальные награды проверяются при входе в кабинет (не чаще раза в минуту на игрока) и задачей каждые 10 минут;
  раньше — при каждой загрузке страницы кабинета и по cron.
- Счёт на оплату: QR генерируется на сервере, без стороннего api.qrserver.com.

## Переход со старой CMS

1. Подготовить сервер, задать переменные окружения и открыть MySQL для IP сайта
   ([DEPLOY.md → «Свой сервер»](DEPLOY.md#свой-сервер-ubuntu), шаги 1–3).
2. Задеплоить (на сервер деплой идёт по умолчанию, см. DEPLOY.md, шаг 4).
   CI сам проверит, что кабинет видит базу (`/api/health`). Старая CMS может работать параллельно — данные общие.
3. Проверить вход старым мастер-аккаунтом, список персонажей, создание счёта и его подтверждение в `/admin`.
4. Перенаправить старые адреса на новые (например, в nginx старого хостинга:
   `login.php` → `/login`, `register.php?ref=…` → `/register?ref=…`, `index.php` → `/cabinet`),
   чтобы не потерялись уже разосланные реферальные ссылки.
5. Отключить старую CMS, удалить её файлы с хостинга и **сменить пароль `cms_register`**:
   он хранился открытым текстом в `config.php`.

## Локальная разработка

```bash
cp .env.example .env    # заполнить доступы к тестовой БД
npm run dev
```

Без `NUXT_SESSION_PASSWORD` в dev-режиме используется временный ключ; в production без него лендинг работает,
а запросы кабинета падают с ошибкой (при старте в лог пишется предупреждение).
Проверка реферальных наград вручную: `/admin/referrals` → «Проверить и выдать награды».
