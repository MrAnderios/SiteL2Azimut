# Пополнение баланса (СБП)

Страница пополнения: `/cabinet/donate` (исходник — `app/pages/cabinet/donate.vue`).
Сумма вводится в рублях, монеты начисляются по курсу `payment.coinPrice` из `shared/cabinet.ts` (10 ₽ = 1 Coin of Luck).

## Способ оплаты

Доступен только **СБП** с ручным подтверждением оператором в админ-панели (`/admin`).

- `payments.provider`: для новых счетов — `manual_sbp`. Старые записи с `provider = 'manual'` считаются оплатой по СБП.
- Способ доступен всем пользователям без дополнительных условий.
- Платёжный шлюз не используется: счёт подтверждает оператор после проверки поступления средств.

## Настройка

См. `.env.example`. На сервере значения задаются в `/var/www/azimut/.env` (секреты не коммитить).

```dotenv
# Ссылка СБП для оплаты — на неё ведёт QR на странице пополнения.
# Не задана — используется значение по умолчанию из nuxt.config.ts (runtimeConfig.sbpPaymentUrl).
# NUXT_SBP_PAYMENT_URL=https://...
```

`runtimeConfig.sbpPaymentUrl` кодируется в QR-код на странице счёта. Если ссылка не задана, в QR помещается текст с суммой и кодом платежа.

## Как работает

1. Пользователь создаёт счёт (`POST /api/payments`) — создаётся запись `payments` со статусом `pending` и `provider = manual_sbp`, предыдущие ожидающие счета отменяются.
2. На странице счёта показываются QR/ссылка на оплату по СБП, сумма, количество монет и код платежа; страница периодически опрашивает статус (`GET /api/payments/:id`).
3. Пользователь оплачивает по СБП и указывает код платежа в комментарии к переводу.
4. Оператор подтверждает оплату в `/admin` (`POST /api/admin/payments/:id`, `action: confirm`) — вызывается `markPaymentPaid`: статус становится `paid`, монеты начисляются мастеру, пишется запись в `donate_log`, при необходимости начисляется реферальная комиссия. Повторное подтверждение безопасно (идемпотентно).
5. Оператор может отменить счёт (`action: cancel`). Неоплаченные счета автоматически помечаются истёкшими по таймауту `payment.ttlSec`.

Схема БД не меняется: дополнительные данные счета (способ, валюта, сумма) хранятся в `payments.qr_data` (JSON). Существующие записи платежей не удаляются и не мигрируются; при отображении старые записи трактуются как СБП.

## Проверка

1. На `/cabinet/donate` создаётся счёт, отображаются QR/ссылка СБП, сумма, код и статус «ожидает оплаты».
2. Подтверждение в `/admin` начисляет монеты один раз; повторное подтверждение не дублирует начисление.
3. Отмена и истечение срока корректно меняют статус счёта.
4. В `/var/www/azimut/.env` нет устаревших переменных `NUXT_PAYMENTS_*` (SeverPay); при наличии — удалить и перезапустить сервис `azimut` (вне чата, без передачи секретов).
