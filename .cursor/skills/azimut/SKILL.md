# Azimut

Лендинг сервера Lineage 2, личный кабинет и форум. Nuxt 4, каталог `app/`, бэкенд в `server/`. Подробности не копировать в ответ: открывать нужный документ.

| Тема | Документ |
|------|----------|
| Запуск, языки, SEO | `README.md` |
| Кабинет, сессия, монеты | `docs/CABINET.md` |
| Форум | `docs/FORUM.md` |
| Оплата | `docs/PAYMENTS.md` |
| Публичная статистика | `docs/API.md` |
| Стримы | `docs/STREAMS.md` |
| Деплой | `docs/DEPLOY.md` |

Node `^22.21.0` или `^24.11.0`. Локальная база: `npm run db:up` (MariaDB, порт 3307, пользователь `azimut`). Секреты только в `.env`, файл в git не коммитить.

## Куда класть изменение

| Что меняется | Куда |
|--------------|------|
| Текст для игрока | `app/locales/ru.ts` и `app/locales/en.ts`. Тип `en` сверяется с `ru`: новый ключ нужен в обоих |
| Ссылка, дата, рейт, картинка, список стримов | `app/data/site.ts` |
| Курс, лимиты кабинета, id монеты, серверы, код ошибки API | `shared/cabinet.ts` |
| Раздел форума, лимит длины, тип ответа форума | `shared/forum.ts` |
| Чтение и запись форума | `server/utils/forum/`, маршрут только в `server/api/forum/` |
| Стили кабинета / форума | `app/assets/css/cabinet.css` или `forum.css`, не в `main.css` |

Функции из `server/utils/` и `server/utils/forum/` подхватываются сами. В маршруте их не импортировать. Общие типы — из `#shared/cabinet` и `#shared/forum`.

Комментарии короткие, по-русски, и только там, где из кода не ясно зачем так сделано.

## API

Ошибка игроку — `fail(status, code, params?)` из `server/utils/errors.ts`. `code` — значение `ApiErrorCode`. Текст живёт в locales: кабинет в `cabinet.errors`, форум в `forum.errors`. Новый код добавлять в тип, в оба словаря и использовать на сервере. Сырой текст MySQL игроку не отдавать.

Изменяющие `POST`/`PATCH`/`DELETE` под `/api/` уже режет `server/middleware/csrf.ts`. Исключение одно: `POST /api/payments/callback` (подпись шлюза). Новый чужой callback туда не добавлять без такой же проверки.

Запись, которую можно заспамить, ограничивать `rateLimit(key, limit, windowSec)`.

Пока `NUXT_PUBLIC_CABINET_ENABLED=false` (статический FTP-деплой):

- `/login`, `/register`, `/cabinet`, `/admin` уходят в старую CMS. Новый такой путь добавлять в `cabinetPaths` (`app/composables/useCabinetAvailability.ts`).
- Форум не редиректить. Без кабинета страницы `/forum` показывают `forum.unavailable` и стоят `noindex`. Запросы к `/api/forum` с этих страниц не слать (`immediate: cabinetEnabled`).
- Пункт «Форум» в шапке и подвале уже скрыт, пока кабинет выключен.

Публичные `/api/status`, `/api/top`, `/api/castles`, `/api/heroes`, `/api/clans` — только чтение, с кешем. Контракт описан в `docs/API.md`; меняя поля, обновить документ.

Новая индексируемая страница — в `pages` внутри `server/routes/sitemap.xml.ts`. Кабинет, вход и админка в карту сайта не входят и закрыты в `robots.txt`.

## База

Боевой MySQL 5.1.73 без `utf8mb4`. Пулы в `server/utils/db.ts` открываются с `UTF8_GENERAL_CI`. Кодировку соединения не менять и строки в таблицах не перекодировать: кириллица превращается в `?`.

- `cmsDb()` — логин-сервер, по умолчанию `la2`: мастер-аккаунты, платежи, рефералы, форум.
- `gameDb(serverId)` — игровая база. Имя базы = id сервера из `shared/cabinet.ts` (сейчас `la2x3`).

`cms_register` не имеет `ALTER`. Новая таблица кабинета или форума: `CREATE TABLE IF NOT EXISTS` в `server/database/install.sql`. Для форума на уже работающей базе тот же фрагмент ещё и в `server/database/forum.sql`, идемпотентно (колонку, которой может не быть, добавлять проверкой `information_schema`, как `banned`).

Списание монет — одним `UPDATE ... SET coins = coins - ? WHERE coins >= ?`. Начисление и выдача предмета, которые нельзя сделать дважды, — через уникальный ключ или транзакцию, не проверкой «сначала прочитал баланс».

Пароли не менять по формату: мастер-аккаунт — bcrypt, игровой аккаунт — `base64(whirlpool)`.

## Форум

Читать можно без входа. Писать — мастер-аккаунт с именем в `forum_profiles`. Имя игрок задаёт один раз; меняет только администратор.

- «Новости» (`staffOnly`) — темы и ответы только у логина из `NUXT_ADMIN_LOGINS`.
- Закрытая тема: обычному игроку ответ нельзя, администратору можно.
- Забаненный не создаёт темы, не отвечает, не правит текст и не ставит реакции. Администратора бан не касается, банить администратора нельзя.
- Новое сообщение хранится как `markdown`. `plain` не переписывать, пока автор сам не сохранит текст.
- HTML в обход `renderPost` / `sanitizePostHtml` не вставлять. Ссылки — `http`, `https`, `mailto`. Картинки — только `http`/`https`, файлы на сервер не грузятся.
- Удаление стирает строку и пересчитывает `replies`. Автор удаляет только своё последнее видимое сообщение, администратор — любое. Если строк в теме не осталось, тема удаляется вместе с сообщением. Уже скрытые (`hidden = 1`) видны только администратору, вернуть их может только он. Удалить тему можно, только когда видимых сообщений не осталось.
- Реакции `like` и `clown` — под сообщением. На своё ставить нельзя. Удаление сообщения и темы стирает реакции.
- Поиск — по заголовку, `LIKE` с экранированием `%`, `_` и `\`.

Кнопки на странице проверяет `app/utils/forum.ts`, то же правило повторяет сервер. Совпадение не заменяет серверную проверку.

## Проверка

После правок типов и API — `npm run typecheck`.

После правки страницы, вёрстки или данных, которые видит игрок, открыть затронутый маршрут в браузере и пройти сценарий: пустое состояние, ошибка, вторая страница, узкая ширина, если менялась сетка. Скриншот одного кадра не считать проверкой. Кабинет и форум локально: демо `admin` / `azimut`.

Поведение, которое описано в `docs/`, при изменении обновить в том же изменении. Новый документ не заводить, если тема уже есть в таблице выше.

Коммит — только когда просят. Сообщение как в истории: `feat(forum):` / `fix(db):` и одна строка по-русски о том, что изменилось для игрока или сервера.
